**Goal:** Close the three items Phase 12 named and parked. Make `EnableRetryOnFailure` a supported
configuration for the Entity Framework Core ledger store by routing its four transactional methods
through the context's execution strategy. Repair the import residue Redis and the in-memory provider

`StateChangeDispatcher`'s lease-renewal clock from `Stopwatch` to `TimeProvider`. Plus the three

close-out all of it needs.

**Architecture:** No new capability, no new project, no new production option, no storage-format
change. Four production files change. `EntityFrameworkStateLedgerStore.cs` restructures four methods
so each attempt body becomes an execution-strategy delegate, with the existing bounded retry loop
left outside it, and `AcquireAsync` gains a token comparison that stops it denying a lease the caller
actually holds. `RedisStateLedgerStore.ImportAsync` and `InMemoryStateLedgerStore.ImportAsync` each
gain a member-exact removal of the stale change-feed entry. `StateChangeDispatcher` gains a
`TimeProvider` field and a five-argument constructor overload, and `ManualTimeProvider` gains the two
overrides that make a virtual clock reach it. The conformance suite gains one optional `Maintain`
step and two shared tests; the shared Entity Framework Core test seam gains one environment-variable
branch and two teardown guards.

## Four corrections to the research report, verified before planning

Each was checked against the code at `94fd0b7` rather than taken from the report. **An implementer
who finds the report and this plan disagreeing should follow this plan and say so in their report.**

1. **`AcquireAsync`'s lost-acknowledgement replay never reaches `catch (DbUpdateException)`.** The
   report places the fix there (`:409-422`). Traced against the code: the replay opens a **new**
   transaction and re-reads the lease row at `:383-385`, finds it live, and returns `null` from the
   branch at `:387-391` — the top of the method, not the catch. The fix therefore belongs in that
   branch. The catch gets the same comparison because it costs two lines and the re-read is already
   there, but the branch is the one the test exercises, and Task 1 says which is which.

2. **The token must be generated once per `AcquireAsync` call, above the strategy delegate.** The
   report does not say so. Left where it is (`:393`, inside the body), every strategy re-invocation
   mints a fresh token and the comparison can never match, so the fix would be dead code.

3. **`OptionsWithRetryOnFailure<TContext>` is kept, not deleted.** The report's sizing for A2 says to
   delete it once `Configure` learns the environment variable. The deterministic retry tests must
   force a retrying strategy **regardless** of that variable, or they silently skip in exactly the
   run that is supposed to prove a retry happened. It keeps its name, gains an optional `configure`
   parameter, and its doc comment is rewritten.

4. **There is no `tests/Statesman.Testing.Tests` project, and this phase does not create one.**
   `ManualTimeProviderTimerTests` lives in `tests/Statesman.Tests/`, which already references
   `Statesman.Testing`. Task 5's `GetTimestamp` tests go in that file.

### Value domain and failure semantics of every primitive adopted

Read this table before writing any code. Each row is a primitive whose value domain decides a design
choice; getting one wrong is how a phase ships a silent defect. Every row was verified against the
shipped assemblies or the repository at `94fd0b7`.

| Primitive / mechanism | Value domain and semantics | What happens when the assumption fails |
|---|---|---|
| `IExecutionStrategy` from `context.Database.CreateExecutionStrategy()` | With no `EnableRetryOnFailure`, a `NonRetryingExecutionStrategy`: it invokes the delegate **exactly once** and rethrows. `RetriesOnFailure` is `false`. With retry on, `SqlServerRetryingExecutionStrategy` / `NpgsqlRetryingExecutionStrategy`, six attempts by default with backoff. | This is why the outer `MaxWriteAttempts` loop cannot be deleted: without it the bootstrap `23505` retry disappears for every consumer who has not opted in. It is also why "behaviour is unchanged by default" is demonstrable — one invocation over a fresh context makes `ChangeTracker.Clear()` a no-op. |
| `ExecutionStrategyExtensions.ExecuteAsync<TResult>` | **Verified by reflection over `Microsoft.EntityFrameworkCore` 10.0.11**: `ExecuteAsync<TResult>(this IExecutionStrategy, Func<CancellationToken, Task<TResult>> operation, CancellationToken)` exists, alongside state-carrying and non-generic forms. The delegate returns `Task<TResult>`, not `ValueTask<TResult>`. | An `async ct => await Helper(...)` lambda over a `ValueTask`-returning helper binds to `Func<CancellationToken, Task<TResult>>` and compiles. If it does not bind, stop and report BLOCKED rather than switching to the four-argument `IExecutionStrategy.ExecuteAsync` form without saying so. |
| `ExecutionStrategyExtensions.ExecuteInTransactionAsync` | **Verified by reflection**: three overloads, and only the one taking a `beginTransaction` factory can set an isolation level. | Using a plain overload silently drops `ReadCommitted` (append, import) and `SnapshotIsolationLevel(context)` (capture) to the provider default, re-opening both engine failures addendum decision 10 measured. Addendum decision 1 rejects it. |
| `DbContext.ChangeTracker.Clear()` | Detaches every tracked entity. Cheap on an empty tracker. Does **not** reset the connection, the transaction, or anything else. | Without it, a replayed delegate's second `context.StatesmanRecords.Add(...)` for the same key throws `InvalidOperationException` naming "cannot be tracked because another instance with the key value … is already being tracked". | `DbTransactionInterceptor.TransactionCommittingAsync` / `TransactionCommittedAsync` | **Verified by reflection over `Microsoft.EntityFrameworkCore.Relational` 10.0.11**: `TransactionCommittingAsync(DbTransaction, TransactionEventData, InterceptionResult, CancellationToken)` returning `ValueTask<InterceptionResult>`, and `TransactionCommittedAsync(DbTransaction, TransactionEndEventData, CancellationToken)` returning `Task`. ### New loop times existing per-call cost

Every task below that turns one call into N, or introduces a loop, states the product.

| Task | The new loop | The existing per-iteration cost | Product, and why it is acceptable |
|---|---|---|---|
| 1 | The execution strategy may invoke each attempt delegate more than once | One full transaction: allocate, read head, insert record, upsert head, commit | Nested **inside** the existing bound of 3, so the worst case is 3 outer attempts times the strategy's own bound (6 by default), each on a fresh or cleared context. Both bounds are the provider's or ours, neither is unbounded, and with the default strategy the product is exactly 3 — today's number. |
| 1 | `ChangeTracker.Clear()` once per delegate invocation | O(tracked entities), which is at most two here (one record, one head) | Constant. On the first invocation over a fresh context it is a no-op, which is the whole behaviour-neutrality argument. |

| 5 | None | — | The conversion replaces three `Stopwatch` calls with three `TimeProvider` calls. No new loop; `GetTimestamp` on `ManualTimeProvider` takes the same monitor `GetUtcNow` already takes. |

```csharp
    /// <summary>Where the injected failure lands, relative to the commit reaching the server.</summary>
    private enum FailureMoment
    {
        /// <summary>Before it: nothing was written, so a replay must succeed outright.</summary>
        BeforeCommit,

        /// <summary>After it: the write is durable and only its acknowledgement was lost.</summary>
        AfterCommit,
    }

    /// <summary>Throws one provider-transient failure at a chosen point, and counts transactions.</summary>
    private sealed class TransientCommitInterceptor : DbTransactionInterceptor
    {
        private readonly FailureMoment _moment;
        private int _thrown;
        private int _transactionsStarted;

        public TransientCommitInterceptor(FailureMoment moment) => _moment = moment;

        public bool Thrown => Volatile.Read(ref _thrown) == 1;

        public int TransactionsStarted => Volatile.Read(ref _transactionsStarted);

        public override ValueTask<DbTransaction> TransactionStartedAsync(
            DbConnection connection,
            TransactionEndEventData eventData,
            DbTransaction result,
            CancellationToken cancellationToken = default)
        {
            Interlocked.Increment(ref _transactionsStarted);
            return ValueTask.FromResult(result);
        }

        public override ValueTask<InterceptionResult> TransactionCommittingAsync(
            DbTransaction transaction,
            TransactionEventData eventData,
            InterceptionResult result,
            CancellationToken cancellationToken = default)
        {
            if (_moment == FailureMoment.BeforeCommit)
            {
                ThrowOnce();
            }

            return ValueTask.FromResult(result);
        }

        public override Task TransactionCommittedAsync(
            DbTransaction transaction,
            TransactionEndEventData eventData,
            CancellationToken cancellationToken = default)
        {
            if (_moment == FailureMoment.AfterCommit)
            {
                ThrowOnce();
            }

            return Task.CompletedTask;
        }

        private void ThrowOnce()
        {
            if (Interlocked.CompareExchange(ref _thrown, 1, 0) != 0)
            {
                return;
            }

            // 40001 is a PostgreSQL serialization failure. NpgsqlRetryingExecutionStrategy classifies
            // it as transient, so the strategy re-invokes the delegate; DbException.IsTransient also
            // reports true for it, which is why the store's delegate rolls back and RETHROWS rather
            // than looping -- the strategy has to get first refusal or this test proves nothing.
            throw new PostgresException("injected serialization failure", "ERROR", "ERROR", "40001");
        }
    }

    /// <summary>Counts contexts handed out, which is what separates a strategy retry from a loop retry.</summary>
    private sealed class CountingDbContextFactory<TContext> : IDbContextFactory<TContext>
        where TContext : DbContext
    {
        private readonly IDbContextFactory<TContext> _inner;
        private int _created;

        public CountingDbContextFactory(IDbContextFactory<TContext> inner) => _inner = inner;

        public int ContextsCreated => Volatile.Read(ref _created);

        public TContext CreateDbContext()
        {
            Interlocked.Increment(ref _created);
            return _inner.CreateDbContext();
        }

        public Task<TContext> CreateDbContextAsync(CancellationToken cancellationToken = default)
        {
            Interlocked.Increment(ref _created);
            return _inner.CreateDbContextAsync(cancellationToken);
        }
    }
```

```csharp
    // the case it carries is the sequence-row bootstrap race, which no provider classifies as
    // transient, so a strategy would never retry it.
    private async ValueTask<StateAppendResult?> AppendAttemptAsync(
        TContext context,
        StateAddress address,
        StateWriteCondition condition,
        StateCommit commit,
        int attempt,
        CancellationToken cancellationToken)
    {
        // FIRST statement, and load-bearing. A retrying strategy re-invokes this delegate against
        // THIS SAME context, so an entity Added by a rolled-back attempt is still Added here and the
        // replay's Add of the same key throws. Addendum decision 11 named this hazard when it
        // rejected IExecutionStrategy for Phase 12; this line is the answer to it. On the first
        // invocation over a freshly created context it is a no-op, which is the whole reason
        // behaviour is unchanged under the default non-retrying strategy.
        context.ChangeTracker.Clear();
        await using var transaction = await context.Database
            .BeginTransactionAsync(IsolationLevel.ReadCommitted, cancellationToken)
            .ConfigureAwait(false);
        try
        {
            // Allocated INSIDE the delegate, with everything derived from it. The increment is rolled
            // back with the transaction, so a replay legitimately allocates a new position; a
            // position hoisted above the strategy would be reused after a rollback and break the
            // density guarantee addendum decision 10 establishes.
            long? allocated = await TryAllocatePositionAsync(context, cancellationToken).ConfigureAwait(false);
            if (allocated is not long position)

                if (attempt < MaxWriteAttempts)

                    return null;
                }

                throw new InvalidOperationException(

                value.Path == address.Path.Value &&
                value.Partition == address.Partition.Value,
                cancellationToken).ConfigureAwait(false);

                // rejected append burns no position and this provider's positions stay dense.
                //

                // match, and returns Conflict with that record. That is byte-for-byte the behaviour
                // docs/providers/index.md already documents for the internal retry, so running inside
                // an execution strategy changes nothing about it.
                await transaction.RollbackAsync(cancellationToken).ConfigureAwait(false);
                return StateAppendResult.Conflict(current);

                GlobalPosition = position,

            await RollbackQuietlyAsync(transaction, cancellationToken).ConfigureAwait(false);

            {

            }

            // The write condition still matches, so this was not an optimistic
            // concurrency conflict. Preserve the provider failure for the caller.
            throw;
        }
```

```csharp
        await using var transaction = await context.Database
            .BeginTransactionAsync(IsolationLevel.Serializable, cancellationToken)
            .ConfigureAwait(false);

        try
        {
            DateTimeOffset now = _timeProvider.GetUtcNow();
            StatesmanLedgerLease? existing = await context.StatesmanLeases
                .SingleOrDefaultAsync(value => value.LeaseId == leaseId, cancellationToken)
                .ConfigureAwait(false);

            if (existing is not null && existing.ExpiresAt > now)
            {
                await transaction.RollbackAsync(cancellationToken).ConfigureAwait(false);

                // THIS is the branch a lost-acknowledgement replay reaches -- not the catch below.
                // The row this caller wrote is committed, so the re-read above finds it live, and
                // without the token comparison the method reports "another caller won" about a lease
                // this caller holds. A matching token can only mean the live row is our own write.
                return existing.Token == token
                    ? new EntityFrameworkLease<TContext>(_factory, leaseId, token, _timeProvider)
                    : null;
            }

            DateTimeOffset expiresAt = now + ttl;
            if (existing is null)
            {
                context.StatesmanLeases.Add(new StatesmanLedgerLease { LeaseId = leaseId, Token = token, ExpiresAt = expiresAt });
            }
            else
            {
                existing.Token = token;
                existing.ExpiresAt = expiresAt;
            }

            await context.SaveChangesAsync(cancellationToken).ConfigureAwait(false);
            await transaction.CommitAsync(cancellationToken).ConfigureAwait(false);
            return new EntityFrameworkLease<TContext>(_factory, leaseId, token, _timeProvider);
        }
        catch (DbUpdateException)
        {
            await transaction.RollbackAsync(cancellationToken).ConfigureAwait(false);
            await using TContext verifyContext = await _factory.CreateDbContextAsync(cancellationToken).ConfigureAwait(false);
            StatesmanLedgerLease? current = await verifyContext.StatesmanLeases
                .AsNoTracking()
                .SingleOrDefaultAsync(value => value.LeaseId == leaseId, cancellationToken)
                .ConfigureAwait(false);
            if (current is not null && current.ExpiresAt > _timeProvider.GetUtcNow())
            {
                // Symmetric with the live-lease branch above, for the same reason, and narrower: a
                // duplicate-key insert whose winning row turns out to carry this caller's own token.
                // The branch above is the one the gated test exercises; this one is here so the two
                // exits from the method cannot disagree about what a matching token means. Otherwise
                // this is the documented "someone else got it" outcome, not a failure.
                return current.Token == token
                    ? new EntityFrameworkLease<TContext>(_factory, leaseId, token, _timeProvider)
                    : null;
            }

            // The lease is not actually held by anyone else, so this was not an optimistic
            // concurrency conflict. Preserve the provider failure for the caller.
            throw;
        }
    }
```

```csharp
        StateAddress[] targets,

            ? IsolationLevel.ReadCommitted
```

```csharp
                // the prune-during-import race no provider classifies as transient. A fresh context
                // on the next iteration re-reads, finds the row gone, and inserts it -- which is what
                // an exact, idempotent import should do.

    // One attempt of ImportAsync, as the execution strategy's delegate. A false return means "the
    // outer loop should try again on a fresh context"; it carries only the sequence-row bootstrap
    // race, for the same reason AppendAttemptAsync returns null for it.
    private async ValueTask<bool> ImportAttemptAsync(
        TContext context,
        StateRecord record,
        int attempt,
        CancellationToken cancellationToken)
    {
        // See AppendAttemptAsync: the strategy may re-invoke this against the same context, so every
        // entity a rolled-back attempt tracked has to be detached before this one tracks its own.
        context.ChangeTracker.Clear();
        await using var transaction = await context.Database
            .BeginTransactionAsync(IsolationLevel.ReadCommitted, cancellationToken)
            .ConfigureAwait(false);
        try
        {
            if (!await TryAdvancePositionAsync(context, record.GlobalPosition, cancellationToken).ConfigureAwait(false))
            {
                await transaction.RollbackAsync(cancellationToken).ConfigureAwait(false);
                if (attempt < MaxWriteAttempts)
                {
                    return false;
                }

                throw new InvalidOperationException(
                    "The global-position sequence row could not be created after several attempts.");
            }

            StatesmanLedgerRecord? existing = await context.StatesmanRecords.SingleOrDefaultAsync(value =>
                value.Root == record.Address.Root &&
                value.Path == record.Address.Path.Value &&
                value.Partition == record.Address.Partition.Value &&
                value.Revision == record.Revision,
                cancellationToken).ConfigureAwait(false);
            if (existing is null)
            {
                context.StatesmanRecords.Add(ToEntity(record));
            }
            else
            {
                // Replica import is exact. A matching key does not prove the cached
                // record is identical to the cold authority.
                Apply(existing, record);
            }

            StatesmanLedgerHead? head = await context.StatesmanHeads.SingleOrDefaultAsync(value =>
                value.Root == record.Address.Root &&
                value.Path == record.Address.Path.Value &&
                value.Partition == record.Address.Partition.Value,
                cancellationToken).ConfigureAwait(false);
            if (head is null)
            {
                context.StatesmanHeads.Add(ToHead(record));
            }
            else if (head.Revision <= record.Revision)
            {
                Apply(head, record);
            }

            await context.SaveChangesAsync(cancellationToken).ConfigureAwait(false);
            await transaction.CommitAsync(cancellationToken).ConfigureAwait(false);
            return true;
        }
        catch (Exception exception) when (
            (IsTransientFailure(exception) || exception is DbUpdateConcurrencyException)
            && attempt < MaxWriteAttempts)
        {
            // One case wider than AppendAttemptAsync's filter. Dropping to ReadCommitted means a
            // concurrent PruneAsync can delete the record this import is replacing between the read
            // above and the write below, which surfaces as DbUpdateConcurrencyException (zero rows
            // affected). Serializable did not protect this: it failed the import outright on
            // PostgreSQL and blocked the prune for the full command timeout on SQL Server. Rolled
            // back and RETHROWN rather than looped, so a retrying execution strategy gets first
            // refusal; the outer loop absorbs what it gives up on. Retrying is safe because every
            // step here is idempotent: the attempt is rolled back, the max-advance is idempotent by
            // construction, and the record and head writes are exact replaces.
            await RollbackQuietlyAsync(transaction, cancellationToken).ConfigureAwait(false);
            throw;
        }
    }
```

```csharp
    public async Task Compaction_collapses_a_line_repeated_with_both_line_endings()
    {

        // same content -- and TryParseChangeFeedLine parses the decoded string, so those two are the
        // same (position, address, revision) and the feed yields that record twice. Under a raw-byte
        // comparison the CRLF variant survives, this log compacts 3 lines to 2, and the feed keeps
        // yielding one record twice: the exact defect the collapse exists to remove.
        //
        // The shipped writer never emits a carriage return -- AppendChangeFeedEntryUnsafeAsync builds
        // string.Join('\t', ...) + "\n" -- so this shape is only reachable from a foreign or

            {

                await store.AppendAsync(address, StateWriteCondition.Absent, Commit("v1"));
```
