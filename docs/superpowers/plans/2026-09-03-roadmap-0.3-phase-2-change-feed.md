# ROADMAP 0.3 Phase 2a: Durable Change Feed Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add `IStateChangeFeed` as a native, directly-implemented capability on every shipped
provider (InMemory, EntityFrameworkCore, Redis, FileSystem, Tiered), giving callers a
cursor-resumable, cross-stream ("everything since position X") view of a store's history — the
durable half of ROADMAP 0.3's Phase 2. Provider-native push notifications
(`IStateChangeNotifier`) are deliberately **out of scope for this plan** — a separate, smaller
follow-on plan, since they're a genuinely optional acceleration layered on top of this feed, not
a prerequisite for it.

**Architecture:** `IStateChangeFeed : IStateCapability` with `ReadAsync(StateChangeCursor?,
CancellationToken) : IAsyncEnumerable<StateChangeEnvelope>`. Each provider implements it directly
against real cross-stream storage — EF Core via its existing indexed `GlobalPosition` column
(zero schema change), Redis via a new global sorted set populated inside `AppendAsync`'s existing
transaction, FileSystem via a new append-only global index file, and InMemory via a
`ConcurrentQueue<StateRecord>` alongside its existing per-stream dictionary. Tiered delegates
directly to its cold store, matching `ReadHistoryAsync`'s existing (and correct) always-read-cold
behavior. `StateChangeCursor` opaquely wraps a `GlobalPosition` value; callers round-trip it,
never compute with it.

**Tech Stack:** .NET 10, xUnit v3, StackExchange.Redis 3.1.31 (`SortedSetRangeByScoreAsync` with
`Exclude.Start`), EF Core (`AsAsyncEnumerable()`), existing `Statesman.Testing` harness.

**Spec:** `docs/superpowers/specs/2026-09-03-roadmap-0.3-distributed-coordination-design.md`
(Phase 2 section, as revised — the original "generic decorator over `ReadHistoryAsync`" design in
that document's history was infeasible and was replaced with the per-provider-native design this
plan implements, after presenting the trade-off to the user).

## Global Constraints

- Target framework `net10.0`. `Nullable`/`ImplicitUsings` enabled repo-wide;
  `TreatWarningsAsErrors=true`. An `async IAsyncEnumerable<T>` method with `yield return` but no
  genuine `await` inside still needs `await Task.CompletedTask;` as its first statement to avoid
  CS1998 under this repo's warning policy — see the existing precedent in
  `tests/Statesman.Tests/StateCapabilityTests.cs`'s `NonCapableStore.ReadHistoryAsync`.
- Every text file ends with a trailing newline; `.cs` files have no trailing whitespace and never
  contain the literal substrings `TODO`, `FIXME`, or `NotImplementedException`
  (`NotSupportedException` is fine — used for Tiered's defensive "cold doesn't support the feed"
  path). Every `.csproj` must be listed in `Statesman.slnx`. Run `python3 eng/validate.py --report
  artifacts/static-validation.txt` before each commit.
- `StateChangeCursor.Position` is `public` (providers in other assemblies need to read it, and the
  repo has zero `InternalsVisibleTo` declarations by established convention — see Phase 0/1) but
  its doc comment must say callers should treat it as opaque and only round-trip values that came
  from a previous `StateChangeEnvelope.Cursor`, never construct or compare it arithmetically
  themselves.
- `ReadAsync(from: null)` means "everything from the beginning"; `ReadAsync(from: cursor)` means
  strictly-after that cursor's position (exclusive lower bound) — a caller resuming from a
  previously-yielded cursor must never see that same record again.
- Each provider's own change feed reflects records reaching it through **both** `AppendAsync` and
  `ImportAsync` (where the provider implements `IStateLedgerReplica`) — a store's feed must be
  consistent with what `ReadHistoryAsync` can already show for that store, or callers get a
  confusing "I can read it directly but not through the feed" gap.
- No task in this plan changes any existing method's behavior for existing callers — this is
  purely additive (new interface, new members, new fields). Confirm this at every step by running
  the provider's full existing test suite alongside the new tests.

```csharp
/// <summary>
/// Optional capability for a ledger store that can enumerate its own history across every stream,
/// resumable from an opaque cursor. Unlike <see cref="IStateLedgerStore.ReadHistoryAsync"/> (which
/// is scoped to one already-known address), this reads everything the store has recorded since a
/// point in its global order.
/// </summary>
public interface IStateChangeFeed : IStateCapability
{
    IAsyncEnumerable<StateChangeEnvelope> ReadAsync(StateChangeCursor? from, CancellationToken cancellationToken = default);
}

/// <summary>
/// An opaque resume point for <see cref="IStateChangeFeed.ReadAsync"/>. Callers must only
/// round-trip a cursor obtained from a previous <see cref="StateChangeEnvelope.Cursor"/> — never
/// construct, compare, or compute with <see cref="Position"/> directly. It happens to wrap a
/// store's <c>GlobalPosition</c>, but that is an implementation detail providers rely on, not a
/// contract callers may depend on.
/// </summary>
public readonly record struct StateChangeCursor
{
    public StateChangeCursor(long position)
    {
        if (position <= 0)
        {
            throw new ArgumentOutOfRangeException(nameof(position), "A change cursor position must be greater than zero.");
        }

        Position = position;
    }

    public long Position { get; }
}

/// <summary>One record from an <see cref="IStateChangeFeed"/>, paired with the cursor to resume after it.</summary>
public sealed record StateChangeEnvelope
{
    public required StateRecord Record { get; init; }

    public required StateChangeCursor Cursor { get; init; }
}
```

```csharp
public async IAsyncEnumerable<StateChangeEnvelope> ReadAsync(
    StateChangeCursor? from,
    [EnumeratorCancellation] CancellationToken cancellationToken = default)
{
    await Task.CompletedTask;
    long since = from?.Position ?? 0;
    StateRecord[] ordered = [.. _changes
        .Where(record => record.GlobalPosition > since)
        .OrderBy(record => record.GlobalPosition)];

    foreach (StateRecord record in ordered)
    {
        cancellationToken.ThrowIfCancellationRequested();
        yield return new StateChangeEnvelope
        {
            Record = Clone(record),
            Cursor = new StateChangeCursor(record.GlobalPosition),
        };
    }
}
```

(`_changes` as a `ConcurrentQueue<T>` supports lock-free `Enqueue` from inside a caller that
already holds `stream.Gate` — no deadlock risk, no new lock needed. `.Where(...)` on a
`ConcurrentQueue<T>` snapshots via its enumerator; explicit `.OrderBy` guards against any
concurrent-enqueue ordering edge case rather than relying on enqueue order.)

```csharp
public async IAsyncEnumerable<StateChangeEnvelope> ReadAsync(
    StateChangeCursor? from,
    [EnumeratorCancellation] CancellationToken cancellationToken = default)
{
    long since = from?.Position ?? 0;
    string file = ChangeFeedFile;
    if (!File.Exists(file))
    {
        yield break;
    }

    string[] lines = await File.ReadAllLinesAsync(file, cancellationToken).ConfigureAwait(false);
    foreach (string line in lines)
    {
        cancellationToken.ThrowIfCancellationRequested();
        if (line.Length == 0)
        {
            continue;
        }

        string[] fields = line.Split('\t');
        long position = long.Parse(fields[0], CultureInfo.InvariantCulture);
        if (position <= since)
        {
            continue;
        }

        var address = new StateAddress(fields[1], new StatePath(fields[2]), new StatePartition(fields[3]));
        long revision = long.Parse(fields[4], CultureInfo.InvariantCulture);
        FileRecord? record = await ReadFileAsync(HistoryFile(address, revision), cancellationToken).ConfigureAwait(false);
        if (record is null)
        {
            continue;
        }

        yield return new StateChangeEnvelope
        {
            Record = record.ToStateRecord(),
            Cursor = new StateChangeCursor(position),
        };
    }
}
```

The per-address `Gate(address)` semaphore (outer, already held by `AppendAsync`/`ImportAsync`) and
the new `_changeFeedGate` (inner, only held briefly inside `AppendChangeFeedEntryAsync`) are always
acquired in that fixed order, never the reverse — no deadlock risk.
