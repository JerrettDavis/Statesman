## Four corrections to the controller's brief, each measured before planning

**An implementer who finds the brief and this plan disagreeing should follow this plan and say so in
their report.**

1. **The suppression-file generation property is `ApiCompatGenerateSuppressionFile`, not
   `GenerateCompatibilitySuppressionFile`.** The older name is a .NET 6-era spelling and fails
   silently — the pack errors exactly as though no flag were passed. The SDK's own failure message
   names the right one. Addendum decision 42.
2. **`PackageValidationBaselineVersion` must be set in a props file, not on the `pack` command
   line.** The baseline nupkg is a restore-time download. Measured: `-p:` on
   `dotnet pack --no-build` fails with
   `MSB4018: System.IO.FileNotFoundException: Package '…statesman.outbox.0.3.0.nupkg' not found`.
   Addendum decision 40.
3. **Task 2's conditional item is unconditional: `MigrationAttributeMissingWarning` is public and
   costs no `EF1001`, so item (c) lands as code and item (e), the logger sink, lands with it.** The
   brief made both contingent on this measurement. It passed. Addendum decision 44.
4. **Task 4's bound needs two new meter counters to be testable at all.** The brief said "no public
   surface (that is B1)". `StatesmanRuntime` is `internal`, `MaintenanceFailures` is `internal`, the
   repository has **zero** `[InternalsVisibleTo]` and keeps it, and every test seam in this repository
   is a public seam — so the bound is unobservable as the brief describes it. `StatesmanTelemetry` is
   already `public` with a `public Meter` property, so two counters on that existing meter make the
   bound testable through a `MeterListener` while adding **no new type and no new signature**. This is

targets `StatesmanLedgerDbContext` is discovered by every other seam test that runs a
`StatesmanLedgerDbContext` subclass. Adding probe migrations against the base context would change
the migration set the existing tests see. Phase 14 hit this and solved it the same way — see the
comment on `LedgerBaselineTransactionProbeContext`. So the new probes target
`LedgerMinorsProbeContext`, which nothing else constructs.

```csharp
    /// invisible to every other seam test: DeclaredForThisContext only matches a running context

        }

        public UnrelatedLedgerContext(DbContextOptions<UnrelatedLedgerContext> options)

        }
```

```csharp

    // reference equality. A subclass of the declared context is accepted; an unrelated context is
    // not, so a database holding two contexts' migrations in one assembly still keeps them apart.
```

```csharp
namespace Statesman;

/// <summary>The bound on how many maintenance-failure exceptions the runtime retains.</summary>
/// <remarks>
/// <para>
/// <c>StateHandle</c> prunes after every successful append and reports any failure to the runtime, so
/// a store whose prune keeps failing reports once per append for the lifetime of the process. The
/// retention is therefore bounded: the most recent <see cref="MaxRetainedMaintenanceFailures"/> are
/// kept and everything past that is dropped, counted by
/// <c>statesman.maintenance.failures.dropped</c> on <see cref="StatesmanTelemetry.Meter"/>.
/// </para>
/// <para>
/// Public because it is the one number a test or an operator needs, and because the retained
/// collection itself is deliberately internal — a public read-and-clear surface for these
/// diagnostics is a separate, unshipped design question. ROADMAP 0.3 Phase 15, addendum decision 47.
/// </para>
/// </remarks>
public static class StatesmanRuntimeMaintenanceBound
{
    /// <summary>
    /// How many maintenance-failure exceptions the runtime retains. Sixty-four: large enough that a
    /// burst of genuinely distinct failures is still legible to a maintainer reading the collection,
    /// and small enough that the retained set can never itself be the leak. The oldest are dropped
    /// first, because a store that keeps failing produces the same exception repeatedly and the newest
    /// is the one that describes the current state of the world.
    /// </summary>
    public const int MaxRetainedMaintenanceFailures = 64;
}
```

```csharp
        // failure case against a destination that already held a file; this is the cancellation twin

    /// Forwards to an inner store, cancelling the supplied source the first time history is
    /// enumerated — so cancellation lands after the export's header and before its first record.
    /// </summary>
    private sealed class CancellingHistoryStore : IStateLedgerStore, IPartitionCatalog
    {

        private readonly CancellationTokenSource _cancellation;

        public CancellingHistoryStore(InMemoryStateLedgerStore inner, CancellationTokenSource cancellation)
        {
            _inner = inner;
            _cancellation = cancellation;

        public string Name => _inner.Name;

        public ValueTask<StateRecord?> ReadLatestAsync(
            StateAddress address, CancellationToken cancellationToken = default) =>
            _inner.ReadLatestAsync(address, cancellationToken);

        public IAsyncEnumerable<StateRecord> ReadHistoryAsync(
            StateAddress address, StateHistoryOptions options, CancellationToken cancellationToken = default)
        {

        public ValueTask DisposeAsync() => ValueTask.CompletedTask;
    }
```

## Facts every brief carries

Adapted from the research inventory's section F. **Every dispatch brief for this phase repeats this
section verbatim.**

### Process

- Work commits **directly to `main`** — no worktree, no feature branch. Deliberate ruling
  (`docs/superpowers/HANDOVER.md`, "How this effort works", item 2).
- Every commit must pass `python3 eng/validate.py --report artifacts/static-validation.txt` **and**
  leave the build green. Baseline at HEAD `8bacb7e`: **PASS**, `projects: 41`, `test_cases: 411`,
  `csharp_files: 812`, `markdown_files: 73`, `source_lines: 34875`, `all_files: 360`. Cite the metric
  deltas in every task report. (The inventory records `markdown_files: 72`; **73** is the measured
  value on a git-clean tree and is what this plan uses.)
- Subagent reply messages have not reliably reached the controller in this harness. Every implementer
  and reviewer writes its **full report to a file** under
  `.superpowers/sdd/2026-09-12-roadmap-0.3-phase-15-ledger-sweep-and-api-baseline/`; an agent going
  idle means "go read the file", never "the report was lost".
- **Do not trust a review finding without re-reading the file it cites.** Three incidents in this
  effort involved a confident, false technical claim — two nearly entered permanent documentation, and
  a third was a reviewer's "7 broken links" finding that was simply wrong.

### Build and test

- `net10.0` for new code; `TreatWarningsAsErrors=true`; nullable and implicit usings enabled;
  `GenerateDocumentationFile=true`. SDK pinned by `global.json` to `10.0.303`, runner
  `Microsoft.Testing.Platform`.
- xUnit v3. Test projects have an **implicit** `using Xunit;` — do not add it explicitly.
- `Assert.SkipUnless(...)` gates any test needing live infrastructure so it skips cleanly.
- **`dotnet test` has been observed to report "Zero tests ran" / exit 5 for reasons unrelated to
  code**, including for all four projects it was tried on while planning this phase. Run the built
  xUnit v3 executable directly: `tests/<Project>/bin/<Debug|Release>/net10.0/<Project>.exe`. The
  `redis-tests` CI step is deliberately one `dotnet test` **per project** for the same reason — extra
  project paths handed to one runner produce "Zero tests ran".
- Local build flags that avoid contention: `-m:1 -p:UseSharedCompilation=false`.
- Environment variables read by tests, all optional: `STATESMAN_TEST_REDIS`,
  `STATESMAN_TEST_SQLSERVER`, `STATESMAN_TEST_POSTGRES`, `STATESMAN_TEST_EF_RETRY`,
  `STATESMAN_MEASURE_FEED_SCAN`, `STATESMAN_MEASURE_INMEMORY_DRAIN`, and this phase's new
  `STATESMAN_MEASURE_OUTBOX_CURSOR_WRITE`. **PowerShell environment variables do not survive between
  tool calls** — set them inline in the same command as the test run.
- Shared test helpers live in `tests/Shared/`: `EntityFrameworkTestProvider.cs` (the only sanctioned
  way to configure an engine — no test may hard-code `.UseSqlite(`; its `Options<TContext>` is
  constrained to `where TContext : DbContext`, so an unrelated context works) and
  `PausingTimeProvider.cs` (pauses on the Nth `GetUtcNow()`; every test using it must prove the pause
  was entered).
- `.config/dotnet-tools.json` pins `dotnet-ef` 10.0.11 repository-wide.
- **`rtk` rewrites `grep` even inside pipelines and after `rtk proxy`. Never redirect grep output into
  a file** — it has clobbered a ledger before. Edit with Write/Edit or single-quoted heredocs, and
  read exact text with `sed -n`.

### Repository invariants to preserve

- Zero `[InternalsVisibleTo]` attributes anywhere; the core `Statesman` package has **zero** external
  dependencies beyond `Statesman.Abstractions`. Both deliberate, preserved through fourteen phases.
  Every test seam is a public seam.
- A change that adds **no** capability must **not** touch `docs/architecture/capabilities.md` or
  `tests/Statesman.Capabilities.Tests/CapabilityMatrixTests.cs` — the Phase 10–14 precedent, stated in
  every one of those five close-outs. **This phase adds none.**
- Entity Framework Core migration ids are permanent public contract: never renamed, removed or
  regenerated. The six shipped ids are ledger `20260912015451`, `20260912020701`, `20260912020709`
  and outbox `20260912021847`, `20260912021856`, `20260912021904`.
- `dotnet pack` over `src` produces **22** nupkgs (16 + the six Phase 14 migration packages). Tasks 7
  and 8 both re-check that number.
- A new net10-only project must carry its own `<TargetFramework>` (which wins — measured, Phase 14
  decision 31). Task 7 makes that the only mechanism.
- Package version comes from `version.json` (Nerdbank.GitVersioning), not from the tag;
  `eng/check-release-tag.sh` fails a release whose tag does not name the version `version.json`
  yields. `main` sits at `0.4.0-alpha.{height}`.
- **After Task 8, every public-surface change needs either compatibility or a suppression entry.** A
  suppression is added only with a `### Breaking` changelog entry and a row on
  `docs/reference/api-compatibility.md`.

### Evidence discipline, learned the hard way in Phases 7–14

- Every regression test needs a **RED-at-baseline proof**, and every mechanism claim needs a
  **break-the-mechanism lever** that reproduces the predicted failure text. **A pinning test that
  passes at baseline is not a regression test and must not be reported as one** — it needs a lever
  instead, and this plan names which tests are which.
- A plan's predicted RED count is a claim the implementer may disprove — report the observed count and
  the reason it differs.
- A test that pins an interval or timeout to zero is the one value that can mask the bug (Phase 7 C1).
  At least one test must run at the **default** option value.
- Perf changes are measured in **Debug and Release** before landing; a complexity argument that
  measures slower is a regression (Phase 12 D4, reverted byte-identical).
- Prefer gating one actor so a count is exact over widening a numeric bound (the macOS flake lesson).
- Documentation takes its numbers from task **reports**, never from briefs.
- `fsync` is not black-box provable in this repository; the evidence for a durability change is a
  round-trip test at both option values plus a measurement.
- **Research probes must use the consumer's shape.** A probe that measures a base class where the
  repository uses a subclass measures the wrong thing (the Phase 14 lesson).
- **A "strictly better" ruling that drops documented behaviour is a regression.** Task 3's
  history-file filter is this phase's example.
