# ROADMAP 0.3 Phase 21 — STM004 completeness, the ownership walk, and Redis Cluster Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development
> (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use
> checkbox (`- [ ]`) syntax for tracking.

**Goal:** Close STM004's collection-membership and mutator-name gaps, add the conversion arms the
shared ownership walk never had, give both analyzer rules one hop of alias tracking, pin the Redis
read loop's widened-type operand with a unit-level fact, document the `event` asymmetry, correct six
documentation claims the pre-flight research measured as wrong, ship ROADMAP 0.2 bullet 6 as an
opt-in `RedisKeyLayout` option plus a `redis-cluster` CI job, and stop Dependabot proposing Roslyn.

**Architecture:** Ten tasks, strictly sequential. Task 1 is Dependabot hygiene and is independent of
everything. Tasks 2, 3 and 5 each widen a shipped analyzer rule and each is its own review checkpoint.
Task 4 is disjoint: one new Redis test file and no production change. Task 6 is documentation plus two
pinning facts and changes no analyzer. Task 7 collects every documentation correction the earlier tasks
leave pending, so the analyzer guide's STM004 section is rewritten once with all three changes in view
rather than three times. Task 8 adds the `RedisKeyLayout` option and needs standalone Redis. Task 9 adds
the CI job and needs a cluster. Task 10 is the close-out. **Keep implementers strictly sequential even
where the dependency graph would allow otherwise.**

**Tech Stack:** .NET 10 (`net10.0` for every test project, `netstandard2.0` for both analyzer
assemblies), SDK 10.0.303 pinned by `global.json`, Roslyn 5.6.0, StackExchange.Redis **3.2.1**, xUnit v3
**4.0.1**, `Microsoft.CodeAnalysis.CSharp.CodeFix.Testing` 1.1.4. **No new project. No new central
package pin. No new diagnostic id. No new NuGet package. No storage-format change and no Entity
Framework Core migration. No capability.** One new public enum and one new public property, both
additive; one new environment variable; one new CI job; three new files.

**Spec:** `docs/superpowers/specs/2026-09-03-roadmap-0.3-distributed-coordination-design.md` — the
"Phase 21 — STM004 completeness, the ownership walk, and Redis Cluster (2026-09-14)" section, plus the
"Addendum (pre-Phase-21, 2026-09-14)" recording decisions 111 through 121. Research and every
measurement it cites: `.superpowers/sdd/2026-09-14-phase-21-research/report.md`. Conventions:
`docs/superpowers/HANDOVER.md` lines 1 to 72.

## Seven corrections to the research and to this phase's brief, each measured before planning

**An implementer who finds the research, the brief and this plan disagreeing should follow this plan
and say so in their report.** Every claim here was measured at `98bf54f` in a scratch worktree that was
removed afterwards; `git worktree list` showed only the main tree and `git status --short` in the main
tree was empty.

1. **The null-forgiving arm's two obvious facts do not discriminate, and this plan ships two different
   ones.** The research named `((PlainHolder)s.Plain).Value = 1`, `((List<int>)s.IColl).Add(1)` and
   `(s.IColl as List<int>)!.Add(1)` and said "three `switch` arms close it". Three arms do close it,
   but `s.Plain!.Value = 1` and `s.Plain!.Items.Add(1)` — the natural rows for the third arm — **pass
   without it**: Roslyn's `GetSymbolInfo` on a suppression answers with the operand's symbol, so the
   walk finds the owner without ever stepping. Measured: with the arm deleted, both rows still pass.
   The rows that discriminate are `((PlainBag)s.Plain)!.Value = 1` and `(s.Coll as List<int>)!.Add(1)`,
   and those are the rows Task 3 ships.
2. **The research's alias prototype has eight bail-outs; this plan ships four.** Its lambda and
   local-function bail-out fires on nothing that the assignment and `out`/`ref` checks do not already
   catch, and what it uniquely suppresses is a lambda that only *reads* the alias, which is a true
   positive. Its unary bail-out tests the node type, and a postfix `!` is a
   `PostfixUnaryExpressionSyntax` too, so it would silence every null-forgiving mention of an alias;
   Task 5 narrows it to the four increment and decrement `SyntaxKind`s and pins it with a fixture type
   that defines `operator ++`.
3. **The read-loop seam still works at StackExchange.Redis 3.2.1**, which `98bf54f` moved to after the
   research ran at 3.1.31. Measured by reflection over the 3.2.1 assembly: `ChannelMessageQueue` has
   exactly one non-public instance constructor, `(ref RedisChannel, RedisSubscriber)`, one
   `Void MarkCompleted(System.Exception)`, and the `_queue` field the readiness probe reads. The
   research's `RedisConnectionException` five-argument overload note also still holds: the
   two-argument overload is `[Obsolete]` and `TreatWarningsAsErrors` makes that `error CS0618`.
4. **There is no shared Redis test provider for this phase's brief to name, and no canonical list of
   the `STATESMAN_TEST_*` variables in the user-facing documentation.** `tests/Shared/` holds
   `EntityFrameworkTestProvider.cs`, `PausingTimeProvider.cs` and `PruneFailingStore.cs`, and every
   Redis test reads `STATESMAN_TEST_REDIS` itself — forty `new RedisStateLedgerStore(...)` call sites
   across ten files in three projects. Task 8 creates the shared place the brief assumed existed,
   `tests/Shared/RedisTestLayout.cs`, and sweeps all forty sites; Task 9 creates the list, as a new
   "Test environment variables" section in `CONTRIBUTING.md`. The only non-`superpowers` documentation
   that mentions any of these variables today is `docs/providers/index.md:162`, and Task 9 corrects
   that sentence too, because the cluster job falsifies it.
5. **`docs/reference/public-api.md` names no provider options class and there is no API-listing
   test.** Measured: zero occurrences of the string `Options` in that file, and a search for any test
   or script that reads it returns only `docs/toc.yml`. The brief asked for both to be updated in the
   same task; Task 8 adds one sentence to that page and records that it is the first provider option
   the page has ever listed, and says in its report that no API-listing test exists to update.
6. **`eng/validate.py` does parse `.github/dependabot.yml` and `.github/workflows/ci.yml`, and neither
   check is a problem here.** It loads every `.yml` with `yaml.safe_load`, rejects any tab character,
   and requires the literal tokens `groups:` and `update-types:` in `dependabot.yml` and `--coverage`,
   `--coverage-output-format cobertura`, `codecov/codecov-action` and `reportgenerator` in `ci.yml`.
   Task 1's `ignore:` entry and Task 9's job preserve all six; measured PASS after each.
7. **`rtk` corrupts backslashes written through a Bash heredoc.** Measured this session: a
   `python3 - <<'PYEOF'` block that wrote a YAML line-continuation backslash produced a file with the
   continuation consumed, and one that wrote the two characters `\r` produced a literal carriage
   return inside the YAML, which `yaml.safe_load` then read as a line break. Both silently broke
   `ci.yml` and `eng/validate.py` reported `FAIL`. **Write files with the Write and Edit tools, never
   through a heredoc, whenever the content contains a backslash.** Task 9's job text avoids
   continuations and `\r` entirely for the same reason.

  touched: `git add <exact paths>`, never `git add -A`, `git add .`, or a bare `git commit -a`. Never

  `src/Statesman.Analyzers` (`ManagedStateCollectionMutationAnalyzer.cs` and `ManagedStateOwnership.cs`,
  and **no other file** — no new descriptor, no new analyzer class, no help-link change) and
  `src/Statesman.Persistence.Redis/RedisStateLedgerStore.cs` (one enum, one property, one private
  helper, five repointed key builders). **No storage-format change, no migration, no capability, no new
  central package pin and no new project.** `docs/architecture/capabilities.md`,
  `docs/reference/api-compatibility.md`, `tests/Statesman.Capabilities.Tests/` and every
  `CompatibilitySuppressions.xml` are untouched by every task. `docs/reference/public-api.md` is touched
  by Task 8 **only**, and by one sentence. A task that finds itself editing any of the others has
  drifted and reports BLOCKED.
- **Every commit must leave `python3 eng/validate.py --report artifacts/static-validation.txt` at
  PASS** and `dotnet build Statesman.slnx -c Debug -m:1 -p:UseSharedCompilation=false` green.
  `artifacts/` is git-ignored. **Reconcile `projects`, `tracked_files` and `test_cases`; treat
  `all_files` as monotonic; reconcile none of the others.** `csharp_files`, `json_files`,

- **The SDD workspace is git-ignored** (`.superpowers/sdd/.gitignore` is a single `*`), so no report
  file any agent writes is ever committed and none of them moves `tracked_files`.
- **Every analyzer warning is an error in this repository.** `TreatWarningsAsErrors=true` repository
  wide with only `CS1591` in `NoWarn`; nullable and implicit usings enabled;
  `GenerateDocumentationFile=true`. Every new public type and member in this plan carries a `///`
  comment with a `<param>` for each parameter, and the verified code has them — do not strip them.
- **The compile traps, all measured in this repository:**
  - `--` inside an XML `<!-- … -->` comment in a `.props` or `.csproj` is an **XML parse error**.
    Inside a `///` comment it is legal here, and this plan still avoids new `--` in `///` text. Every
    code comment in this plan that wants a dash uses a single hyphen or a comma.
  - `if (false)` levers are **`CS0162`** under `TreatWarningsAsErrors`. Write `&& false` on a
    non-constant.
  - `Assert.Single(x.Where(pred))` is **`xUnit2031`**. Use `Assert.Single(x, pred)`.
  - A **public** method on a test class that is not a `[Fact]` or `[Theory]` is **`xUnit1013`**. Task
    4's helpers live in classes of their own for exactly this reason.
  - An `async` method with no `await` is **`CS1998`**.
  - `RedisConnectionException(ConnectionFailureType, string)` is `[Obsolete]`, so
    `TreatWarningsAsErrors` makes it `error CS0618`. Use the five-argument overload.
- **Central package management only.** Never put `Version` or `VersionOverride` on a
  `PackageReference`.
- **xUnit v3, with an implicit `using Xunit;`** in every test project. Do not add it explicitly.
  `Assert.SkipUnless(...)` gates any test needing live infrastructure. An honest "No" is a skip with a
  reason, never a silent pass. Pass `TestContext.Current.CancellationToken` to any awaited framework
  call that accepts one.
- **Build:** `dotnet build <project-or-solution> -m:1 -p:UseSharedCompilation=false`. The two flags
  avoid local build contention under multi-agent load.
- **Run the built xUnit v3 executable directly**, at
  `tests/<Project>/bin/Debug/net10.0/<Project>.exe`, after a `dotnet build`. **Never `dotnet test`** —
  the CLI has been observed to report "Zero tests ran" / exit 5 locally for reasons unrelated to code.
  The filters are `--filter-class '<pattern>'` and `--filter-method '<pattern>'`; `--filter` is VSTest
  syntax and does not work here. Add `--no-ansi --progress off` when you want parseable output.
- **Redis:** `STATESMAN_TEST_REDIS=localhost:6379`, set **inline in the same command** as the test run,
  because PowerShell environment variables do not survive between tool calls. The container
  `statesman-redis` is already running and **must be left running**.
- **`rtk` rewrites `grep` and `git` even inside pipelines and after `rtk proxy`, and truncates or
  swallows their output.** **Never redirect `grep` or `git diff` into a file, and never trust an empty
  result from either.** Read exact text with `sed -n 'A,Bp' file`, and scan changed files with the
  Python snippet in "The commands every task uses". Edit files with the Write/Edit tools. **And never
  write a backslash into a file through a Bash heredoc** (correction 7).
- **Never `cd` in a compound command; use absolute paths.**
- **Every new pinning fact needs a break-the-mechanism proof named in its own step, and every lever in
  this plan was applied, observed and reverted while the plan was written.** Eighteen are named, with
  the exact failure count each produced. **One is named in advance as reaching fewer rows than it
  guards** — that is a finding, not an omission, and the task reports it as one. **Do not fake a RED**,
  and do not "fix" a lever that behaves as this plan predicts.
- **One lever per operand.** A rule with `or`/`and` gets one break-the-mechanism lever **per operand**.
  That is why Task 2 has four and Task 5 has four.
- **Models.** Implementers: **Sonnet** for every task that compiles or runs code — Tasks 2 through 10.
  **Haiku** is permitted only for Task 1 (Dependabot) and for pure transcription. Reviewers: **Sonnet**.

  cluster. Reviewers and scanners are read-only and never dispatch subagents; implementers never
  dispatch subagents either. That rule belongs in the dispatch prompt itself, not only here.

/// Builds and faults StackExchange.Redis's sealed <see cref="ChannelMessageQueue"/>, the one
/// concrete type <see cref="ISubscriber.SubscribeAsync(RedisChannel, CommandFlags)"/> hands back.
/// Its only constructor is internal, takes <c>(ref RedisChannel, RedisSubscriber)</c> and accepts a

/// the exception surfaces from <c>MoveNextAsync</c> unwrapped. Measured against

internal static class ReadLoopQueue
{
    private static readonly Type QueueType = typeof(ChannelMessageQueue);

    public static ChannelMessageQueue New(string name)
    {
        ConstructorInfo constructor = QueueType.GetConstructors(BindingFlags.Instance | BindingFlags.NonPublic)[0];
        var channel = new RedisChannel(name, RedisChannel.PatternMode.Literal);
        return (ChannelMessageQueue)constructor.Invoke([channel, null]);

    public static void Fault(ChannelMessageQueue queue, Exception error)
    {

            "MarkCompleted",
            BindingFlags.Instance | BindingFlags.NonPublic,
            binder: null,
            types: [typeof(Exception)],
            modifiers: null)!;

        return !((ValueTask<bool>)reader.GetType()
            .GetMethod("WaitToReadAsync")!
            .Invoke(reader, [CancellationToken.None])!).IsCompleted;
    }

/// interfaces of 74 and 22 members would otherwise need roughly ninety hand-written stubs, and the
/// store needs four of them. Public because <see cref="DispatchProxy.Create{T, TProxy}"/> requires
/// a public parameterless type.
/// </summary>
public class ReadLoopDispatchProxy : DispatchProxy
{
    /// <summary>Answers a call, or declines it so the default handling below applies.</summary>
    public Func<MethodInfo, object?[]?, (bool Handled, object? Result)>? Handler { get; set; }

    /// <summary>Dispatches one intercepted call.</summary>
    /// <param name="targetMethod">The interface method being called.</param>
    /// <param name="args">Its arguments.</param>
    /// <returns>The handler's answer, or a benign default for disposal and <see cref="ValueTask"/> members.</returns>
    protected override object? Invoke(MethodInfo? targetMethod, object?[]? args)
    {
        if (targetMethod is null)
        {
            throw new NotSupportedException("no method");
        }

        (bool handled, object? result) = Handler?.Invoke(targetMethod, args) ?? (false, null);
        if (handled)
        {
            return result;
        }

        if (targetMethod.Name is "Dispose" or "Close")
        {
            return null;
        }

        if (targetMethod.ReturnType == typeof(ValueTask))
        {
            return default(ValueTask);
        }

        throw new NotSupportedException(targetMethod.Name);
    }
}

```csharp
    /// <summary>
    /// The sole initializer of a local that is provably never rebound, or <see langword="null"/>
    /// when anything about the local makes that unprovable. Each bail-out is a false positive this
    /// rule would otherwise report: a reassigned local no longer holds what its initializer
    /// produced, an <c>out</c>/<c>ref</c> argument may have replaced it, a <c>foreach</c>, pattern
    /// or deconstruction variable has no declarator to read an initializer from, and an increment or
    /// decrement operator rebinds the local through a user-defined operator. There is deliberately no
    /// lambda bail-out:
    /// a rebind performed inside a lambda or a local function is still an assignment or an
    /// <c>out</c>/<c>ref</c> argument and is caught by the two checks above, while a lambda that only
    /// READS the local defers the mutation without changing which object is mutated, so bailing on
    /// capture alone would lose a true positive.
    /// </summary>
    /// <param name="context">The syntax-node context whose semantic model resolves the local.</param>
    /// <param name="identifier">The identifier the walk arrived at.</param>
    /// <returns>The initializer expression to continue the walk through, or <see langword="null"/>.</returns>
    private static ExpressionSyntax? SingleInitializerOf(
        SyntaxNodeAnalysisContext context,
        IdentifierNameSyntax identifier)
    {
        if (context.SemanticModel.GetSymbolInfo(identifier, context.CancellationToken).Symbol
            is not ILocalSymbol local)
        {
            return null;
        }

        // foreach variables, pattern variables and deconstruction designations are not
        // VariableDeclaratorSyntax, so this one check rejects all three.
        if (local.DeclaringSyntaxReferences.Length != 1 ||
            local.DeclaringSyntaxReferences[0].GetSyntax(context.CancellationToken)
                is not VariableDeclaratorSyntax declarator ||
            declarator.Initializer?.Value is not { } initializer)
        {
            return null;
        }

        SyntaxNode? scope = declarator.FirstAncestorOrSelf<BlockSyntax>()
            ?? (SyntaxNode?)declarator.FirstAncestorOrSelf<ArrowExpressionClauseSyntax>();
        if (scope is null)
        {
            return null;
        }

        foreach (IdentifierNameSyntax use in scope.DescendantNodes().OfType<IdentifierNameSyntax>())
        {
            if (use == identifier ||
                use.Identifier.ValueText != local.Name ||
                !SymbolEqualityComparer.Default.Equals(
                    context.SemanticModel.GetSymbolInfo(use, context.CancellationToken).Symbol,
                    local))
            {
                continue;
            }

            if (use.Parent is AssignmentExpressionSyntax assignment && assignment.Left == use)
            {
                return null;
            }

            if (use.Parent is ArgumentSyntax { RefKindKeyword.RawKind: not 0 })
            {
                return null;
            }

            // ++ and -- only. A postfix `!` is also a PostfixUnaryExpressionSyntax and rebinds
            // nothing, so testing the node type alone would silence a true positive.
            if (use.Parent.IsKind(SyntaxKind.PreIncrementExpression) ||
                use.Parent.IsKind(SyntaxKind.PreDecrementExpression) ||
                use.Parent.IsKind(SyntaxKind.PostIncrementExpression) ||
                use.Parent.IsKind(SyntaxKind.PostDecrementExpression))
            {
                return null;
            }
        }

        return initializer;
    }

```

    private static string Hash(StateAddress address) =>
        Convert.ToHexString(SHA256.HashData(Encoding.UTF8.GetBytes(address.Canonical))).ToLowerInvariant();

    /// <summary>
    /// Redis Cluster's own slot function: CRC16/XMODEM of the whole key, or of the substring
    /// between the first <c>{</c> and the first non-empty <c>}</c> after it, modulo 16384.
    /// Reimplemented here because StackExchange.Redis exposes no public equivalent and because a
    /// standalone server, which is what this suite usually runs against, refuses CLUSTER KEYSLOT.
    /// </summary>
    private static int HashSlot(string key)
    {
        int open = key.IndexOf('{', StringComparison.Ordinal);
        if (open >= 0)
        {
            int close = key.IndexOf('}', open + 1);
            if (close > open + 1)
            {
                key = key.Substring(open + 1, close - open - 1);
            }
        }

        ushort crc = 0;
        foreach (byte value in Encoding.UTF8.GetBytes(key))
        {
            crc ^= (ushort)(value << 8);
            for (int bit = 0; bit < 8; bit++)
            {
                crc = (crc & 0x8000) != 0 ? (ushort)((crc << 1) ^ 0x1021) : (ushort)(crc << 1);
            }
        }

        return crc % 16384;
    }

    {
        Operation = StateOperation.Set,
        Status = StateStatus.Ready,
        ValueType = typeof(string).FullName!,
        SchemaVersion = 1,
        Payload = Encoding.UTF8.GetBytes(value),
        Source = "test",
    };

Against a standalone server the default key layout, `RedisKeyLayout.Legacy`, is the only one you need:

```yaml
  # Redis Cluster, single node, all 16384 slots on one master. It exercises CROSSSLOT rejection and
  # Lua KEYS slot validation, which is the whole of the key-layout question; MOVED/ASK redirection
  # needs a multi-node cluster and is deliberately out of scope.
  #
  # This job runs `docker run` in a step rather than declaring the container under `services:`,
  # unlike redis-tests, sqlserver-tests and postgres-tests. It has to: Actions passes a services
  # block only `docker create` options, so it can supply neither the `redis-server` arguments that
  # turn cluster mode on nor the CLUSTER ADDSLOTS that must follow the server coming up.
  redis-cluster:
    needs:
      - static-validation
      - docs
    runs-on: ubuntu-latest
    env:
      STATESMAN_TEST_REDIS: localhost:7010
      STATESMAN_TEST_REDIS_KEY_LAYOUT: SingleSlot
    steps:
      - uses: actions/checkout@v7
        with:
          fetch-depth: 0
      - uses: actions/setup-dotnet@v6
        with:
          global-json-file: global.json
          cache: true
          cache-dependency-path: global.json
      # CLUSTER ADDSLOTS is enough on its own here; redis-cli --cluster create is not needed for a
      # single node that owns every slot. The readiness probe greps rather than comparing a captured
      # string, because redis-cli terminates each line with CR and an equality test would never match.
      - name: Start a single-node Redis cluster
        run: |
          set -euo pipefail
          docker run -d --name statesman-redis-cluster -p 7010:6379 redis:7-alpine redis-server --cluster-enabled yes --cluster-config-file nodes.conf --cluster-node-timeout 5000 --appendonly no
          docker exec statesman-redis-cluster sh -c 'redis-cli cluster addslots $(seq 0 16383)'
          for attempt in $(seq 1 30); do
            echo "attempt ${attempt}"
            if docker exec statesman-redis-cluster redis-cli cluster info | grep -q "cluster_state:ok"; then
              docker exec statesman-redis-cluster redis-cli cluster info
              exit 0
            fi
            sleep 2
          done
          echo "the cluster never reached cluster_state:ok"
          exit 1
      - name: Restore
        run: dotnet restore Statesman.slnx
      - name: Build
        run: dotnet build Statesman.slnx --configuration Release --no-restore
      # One invocation per project, for the same reason redis-tests splits them.
      - name: Test
        run: |
          dotnet test tests/Statesman.Redis.Tests/Statesman.Redis.Tests.csproj --configuration Release --no-build
          dotnet test tests/Statesman.Outbox.Redis.Tests/Statesman.Outbox.Redis.Tests.csproj --configuration Release --no-build
          dotnet test tests/Statesman.Tooling.Tests/Statesman.Tooling.Tests.csproj --configuration Release --no-build
          dotnet test tests/Statesman.Conformance.Tests/Statesman.Conformance.Tests.csproj --configuration Release --no-build
```
